# 데이터 분석 프로젝트 10단계 워크플로우

수집부터 보고(대시보드 반영)까지, 실제 진행했던 AARRR 진단 작업(텔레콤/HR) 방식을 일반화한 워크플로우입니다.

---

## 1단계. 목적/질문 정의
- 이 분석으로 무엇을 답하고 싶은지 먼저 명확히 함
- 프레임워크가 있다면 여기서 정함 (예: AARRR, 이탈진단 등)
- 산출물: "답하고 싶은 질문 리스트"

## 2단계. 데이터 구조 확인 (해석 금지)
- 모든 파일의 행수/열수/컬럼명만 확인
- 아직 분석·해석·계산은 하지 않음
- 산출물: 파일별 구조 표

## 3단계. 메타데이터 정리
- 컬럼별 데이터타입, 결측치 수, 고유값 수 확인
- 결측치가 왜 생기는지(정상적 결측 vs 문제성 결측) 원인만 파악, 처리는 아직 안 함
- 산출물: 컬럼별 메타데이터 표

## 4단계. 가능성 진단 (Feasibility)
- 1단계 질문 각각에 대해 ✅(가능)/⚠️(부분가능)/❌(불가능) 판정
- ✅·⚠️는 근거 파일·컬럼 명시
- ❌·⚠️는 "무엇이 있어야 가능한지" 컬럼 수준으로 명시
- 이 단계까지는 지표를 계산하지 않음
- 산출물: 진단표

## 5단계. 데이터 정합성 및 조인 검증
- 키 값(예: customer_id, 사번)이 파일 간 실제로 매칭되는지 확인
- 조인 시 상대적 기준(예: 가입일 기준 분기차/개월차)이 필요하면 파생 로직 구현
- 조인 후 실제 사용 가능한 표본 수 확인 (표본이 너무 작아지지 않는지 체크)
- 산출물: 조인된 중간 데이터, 표본 크기 확인 결과

## 6단계. 지표 정의 확정
- 지표 계산 전, 정의가 실제로 변별력이 있는지 점검
  (예: "가입 후 7일 활성화"가 전원 100%로 나오면 정의 자체를 재검토)
- 필요시 정의를 재설계하고 그 이유를 기록
- 산출물: 최종 지표 정의 목록

## 7단계. 지표 계산
- ✅ 항목부터 우선 계산
- ⚠️ 항목은 조인/가정을 명시하고 계산
- ❌ 항목은 대리 지표로 억지 추정하지 않고 그대로 남겨둠
- 산출물: 단계별 계산 결과 표

## 8단계. 결과 해석 및 이상 신호 발견
- 예상과 다른 결과, 눈에 띄는 패턴을 별도로 정리
- 표본 크기가 작은 경우 "신호 수준"이라고 명시하고 과도한 확신 피함
- 인과관계와 상관관계를 구분해서 서술
- 산출물: 주요 발견 리스트

## 9단계. 문서화/요약
- 전체 과정(구조 → 메타데이터 → 진단표 → 지표 → 발견)을 하나의 문서로 정리
- 데이터가 추가되거나 수정되면 해당 부분만 업데이트
- 산출물: 요약 문서(md/docx)

## 10단계. 대시보드/공유 반영
- 우선순위가 높은 지표만 추려서 대시보드(Streamlit 등)에 반영
- GitHub 웹 에디터로 코드 수정 → 자동 배포 확인
- 산출물: 배포된 대시보드, 공유 가능한 링크

---

## 참고: 단계 간 원칙
- 2~4단계는 "가능한가"만 보고 계산은 하지 않음 (성급한 지표 계산 방지)
- 5~6단계는 계산 전에 반드시 거쳐야 함 (정의가 잘못되면 7단계 결과 전체가 무의미해짐)
- 데이터가 중간에 추가/수정되면 3~4단계부터 다시 확인 (전체를 처음부터 반복할 필요는 없음)
