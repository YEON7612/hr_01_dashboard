# 설계서: data_hr_referrals.csv

작성일: 2026-08-01
상태: **설계 단계 — 아직 생성되지 않음** (Day3 방식: 실제 인사팀 기록을 확보해야 함. 합성 데이터 아님)

## 배경 — 왜 필요한가 (역산 과정)

기존 `HR_직원.채용경로='추천'`은 "이 사람이 추천으로 들어왔다"는 **상태** 정보만 담고 있고, **누가 추천했는지**는 알 수 없음. 이 둘은 답할 수 있는 질문이 다르므로 중복이 아님 (Day2 원칙).

| | 기존 (HR_직원.채용경로) | 신규 (data_hr_referrals) |
|---|---|---|
| 담는 것 | 이 사람이 추천으로 들어왔다 (상태) | A가 B를 추천했다 (관계/사건) |
| 답 가능 | 추천채용 비중·퇴사율 | 추천인당 성공 건수, 추천을 많이 한 사람이 오래 다니는가 |

## 한 행은 무엇 1개인가
추천 채용 1건 (사건 테이블)

## 답할 수 있게 되는 질문
- 추천인당 성공 건수는 몇 건인가
- 추천을 많이 한 직원이 더 오래 다니는가 (근속연수와의 관계)

**제외한 질문**: 추천 보상 지급 현황 — 회사에 추천 보상 제도가 없음을 확인함 (2026-08-01). Day2 원칙("설명 못 하는 컬럼은 뺀다")에 따라 reward_amount·reward_paid_date 컬럼은 설계에서 제외.

## 컬럼 정의

| 컬럼명 | 타입 | 의미 | 값 범위 | 결측 허용 | 비고 |
|---|---|---|---|---|---|
| referral_id | 문자열 | 추천 식별자 | REF0001~ | 불가 | 기본키 |
| referrer_사번 | 문자열 | 추천한 재직자 | E0001~E0300 | 불가 | HR_직원 참조 |
| referred_사번 | 문자열 | 추천받아 입사한 사람 | E0001~E0300 | 불가 | HR_직원 참조 |
| referral_date | 날짜 | 추천 성사일 | YYYY-MM-DD | 불가 | 피추천인 입사일과 같거나 이전이어야 함 |

## 연결 키
`referrer_사번` · `referred_사번` → `HR_직원.사번`

## 정합성 규칙 (실제 데이터 확보 후 검증할 항목)
1. referrer_사번·referred_사번 모두 HR_직원의 300명 안에 있어야 한다 (참조무결성)
2. referred_사번의 `채용경로`가 '추천'이어야 한다 (기존 상태 필드와 정합)
3. referral_date ≤ referred_사번의 입사일
4. 자기 자신을 추천할 수 없다 (referrer ≠ referred)
5. 채용경로='추천'인 27명 전원이 이 테이블에 정확히 1번씩 referred_사번으로 등장해야 한다 (27건과 정확히 일치해야 함 — 더 많거나 적으면 데이터 오류)

## 심을 패턴 (실제 데이터에서 검증하고 싶은 가설)
추천을 2건 이상 한 재직자는 전원 재직 중이다 (충성도 높은 직원일수록 추천을 많이 한다는 가설). ※ 이건 실제 인사팀 데이터로 확인해야 할 가설이지, 인위적으로 만들 패턴이 아님 — 우리는 실제 회사 데이터를 다루고 있으므로 3주차 실습과 달리 패턴을 "심는" 것이 아니라 "있는지 찾는" 것임에 유의.

## Day2 자가 검증 결과

| 항목 | 통과 여부 |
|---|---|
| ① 그레인 한 문장 | ✅ "추천 채용 1건" |
| ② 완결성 | ✅ 두 질문 모두 계산 가능 |
| ③ 이벤트 4대 요소 | ✅ 누가=referrer_사번, 언제=referral_date, 무엇을=추천행위, 얼마나=해당없음(보상 없으므로) |
| ④ 키 정합성 | ✅ 기존 사번 형식(E0001) 그대로 사용 |
| ⑤ 결측 규칙 | ✅ 결측 허용 컬럼 없음(전부 필수) |
| ⑥ 함정 점검 | ✅ 사후갱신 없음(추천은 1회성 사건) / 시점명확(referral_date) / 중복정의 방지(정합성 규칙 2번으로 채용경로와 대조) |
| ⑦ 불필요 컬럼 | ✅ 보상 관련 2개 컬럼 제거 완료 |

## 최종 결론 (2026-08-01 확정)

**이 테이블은 만들지 않습니다.** 인사팀에 "누가 누구를 추천했는지" 연결하는 실제 기록이 없음을 확인함. 추측이나 대리 지표로 채우지 않고, 정직하게 데이터 부재로 남김.

**Referral 단계 최종 판정**:

| 질문 | 판정 | 근거/사유 |
|---|---|---|
| 추천채용 비중·퇴사율은? | ✅ | HR_직원.채용경로 (기존대로 유지) |
| 추천인당 성공 건수는? | ❌ (영구) | 추천인 연결 기록 자체가 회사에 존재하지 않음 |
| 추천을 많이 한 직원이 더 오래 다니는가? | ❌ (영구) | 상동 |

이 설계서는 "왜 이 질문에 답할 수 없는지"의 근거 문서로 보관함. 나중에 인사팀이 추천인 기록을 남기기 시작하면 이 설계서를 그대로 재사용할 수 있음.
