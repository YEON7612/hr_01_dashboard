## 1. Define — 질문 정의

**오늘의 질문**: 직원들은 왜 퇴사하는가? (부서/직급/근속연수/초과근무/평가/채용경로 중 어떤 요인이 퇴사와 관련 있는가)

- 프레임워크: AARRR을 HR에 맞게 재매핑(채용/온보딩/재직유지/추천채용/성과)해서 사용
- **확정(2026-08-01)**: Referral 단계 중 "추천인당 성공 건수", "추천을 많이 한 직원이 더 오래 다니는가"는 답할 수 없음으로 최종 확정. 인사팀에 추천인-피추천인 연결 기록 자체가 없음을 확인함. 대리 지표로 채우지 않고 ❌로 유지 (근거: `설계서_data_hr_referrals.md`)

## 2. Acquire — 데이터 확보

**확보 경로 확정(2026-08-01)**: ① 원본 반출. 사번만 있고 이름·연락처 등 직접 식별 정보가 없으며, 반출 승인된 상태로 확인함. (Day3 기준: 인사 데이터는 전형적으로 ③ 구조복제후합성이 흔하지만, 이번 경우는 실제 반출이 승인되어 원본을 그대로 사용함)

**확보한 파일**: HR_직원.csv, HR_근태.csv, HR_퇴사이력.csv, HR_평가.csv (이후 HR_직원.csv에 채용경로 컬럼 추가되어 재업로드됨)

**확인 필요**: 앞으로 파일이 추가/수정되어 재업로드될 때, 인코딩 검증을 Acquire 직후 자동으로 하는 절차가 아직 없음 (수작업으로만 발견함)

### 2-1. 신규 구간 확보 (2026-08-01, 셋업①·②)

**데이터 끝 지점 확인 (셋업①)**: 기존 4개 원본 파일을 직접 열어 날짜 범위를 확인함.

| 파일 | 범위 | 끝나는 지점 |
|---|---|---|
| HR_근태.csv | 2025-01 ~ 2025-12 | 2025년 12월 |
| HR_평가.csv | 2025Q1 ~ 2025Q4 | 2025년 4분기 |
| HR_퇴사이력.csv | 2016-03-08 ~ 2025-12-10 | 2025년 12월 10일 |

→ 근태·평가·퇴사이력 3개 파일 모두 2025년 12월에서 끝남. **2026년 1월부터가 신규 확보 구간.**

**확보 경로 판단 (셋업②)**: ④ 공개 데이터를 먼저 검토했으나 기각함 — HR 개인(사번) 단위 + 월별 연속 구조를 가진 공개 데이터셋이 존재하지 않음(Kaggle IBM HR Attrition은 날짜 범위 자체가 없는 단일 스냅샷, 정부 고용보험 통계는 개인 단위가 아닌 전국 집계치라 그레인 불일치). 따라서 **③ 합성 데이터 생성**(1주차 구조를 이어서 지저분하게 만드는 프롬프트) 경로로 확보함.

**확보한 파일**: `HR_근태_2026_1분기_원본수령분.xlsx` (2026년 1~3월, 재직자 269명 기준)

지저분함 요소 6가지를 의도적으로 전부 반영함(Day3·Day4 방식 그대로 적용):
1. 월별 시트 3개 (2026년1월/2월/3월)
2. 2줄 머리글 ("근태현황"이 기본근무시간·초과근무시간을 감쌈)
3. "부서" 컬럼을 병합 셀로 표현
4. 부서별 소계 행을 상세 행 사이에 삽입
5. 초과근무시간을 단위 포함 텍스트로 저장 (예: "13.5시간")
6. 이상근태 여부를 텍스트 없이 셀 배경색만으로 표현 (초록=정상/빨강=이상 — 대응 관계는 문서에 기록하지 않고 별도로만 공유)

**연속성 메모**: 기존 데이터에서 이미 발견됐던 이상치 사번 **E0137**(재무팀, 평균 대비 약 4배 높은 초과근무)의 패턴을 2026년 1~3월에도 그대로 이어감 — Clean 단계에서 정제 스크립트가 이 이상치를 재현 데이터에서도 동일하게 잡아내는지 확인할 예정.

**계획 vs 실제 비교 (Day5 교안 STEP1 기준, 2026-08-01)**: 이번 확보는 사전에 별도로 작성해둔 계획서 없이, 그날 트랙B_셋업가이드의 셋업①②를 그 자리에서 실행한 경우라 "계획"은 사실상 "지저분함 요소 6가지를 의도적으로 넣겠다"는 생성 시점의 설계 그 자체임.
- **계획과 일치한 것**: 의도한 6가지 지저분함 요소(2줄 머리글·병합 셀·소계 행·텍스트 숫자·색상 상태값·다중 시트) 전부가 Profile 진단에서 그대로 확인됨 — 계획대로 반영됨
- **계획에 없었는데 실제로 발견된 것**: "연월 정보가 어떤 셀에도 없고 시트 이름에만 있다"는 점은 6가지 요소를 설계할 때 명시적으로 의도한 항목이 아니었음(우연히 발생한 구조적 부작용) — Profile 3-1에서 처음 발견되어 Confirm 4-1·Clean 5-1에서 정제 규칙(규칙2)으로 새로 추가함. Day3 예시(인코딩 손상처럼 계획에 없던 리스크)와 같은 유형의 "실행하며 알게 된 문제"에 해당함

**확인 필요**: 이 파일은 아직 Profile·Confirm·Clean을 거치지 않은 원본 상태 그대로임. 다음 세션에서 3~5단계(Profile→Confirm→Clean) 진행 필요.

## 3. Profile — 진단

- 행수/열수/컬럼명/데이터타입/결측치/고유값 확인 완료
- 이상값 발견: 특정 사번(E0137)의 근태 데이터가 12개월 내내 평균 대비 3배 이상 높음
- 커버리지 문제 발견: HR_평가·HR_근태는 2025년 한 해분만 존재 (HR_직원 입사일은 2015년까지 존재)

### 3-1. 신규 구간 데이터(`HR_근태_2026_1분기_원본수령분.xlsx`) — 그레인(한 행의 의미) 진단 (2026-08-01)

아직 수정하지 않은 원본 상태에서, "한 행이 무엇을 의미하는지" 확실하지 않은 지점만 정리함(해석·수정 없이 진단만):

1. **그레인이 시트 안에서 섞여 있음**: 269개 행은 "한 사번 × 해당 월"이지만, 시트당 6개 행("OO 소계")은 부서 단위 집계라 같은 표 안에 서로 다른 두 그레인이 공존함
2. **월(기간) 정보가 행 자체에 없음**: 어느 달인지 알려주는 값이 행에 없고 시트 이름에만 있어, 행 하나를 떼어내면(예: 시트 간 병합 시) 자체적으로 기간을 설명하지 못함
3. **기본근무시간(160, 전 행 동일)이 실제 관측값인지 고정 가정값인지 불명확**: 중도입사·휴직 등이 있었다면 160이 아니어야 정상인데 이를 구분할 수 없음
4. **이상근태(빨강 표시) 판정 기준이 통일돼 있지 않음**: "특정 사번(E0137)은 항상 빨강"이라는 사번 단위 규칙과, "그 달 값이 임계값을 넘으면 빨강"이라는 행(사번×월) 단위 규칙이 한 컬럼에 섞여 있음
5. **269명 전원이 매달 빠짐없이 등장하는 것이 무엇을 의미하는지 불확실**: "그 달 실제 근무기록이 있는 사람만 포함"인지 "재직자 명단 기준으로 무조건 다 채운 것"인지 확인되지 않음 — 실제 인원 변동이 있는 데이터를 받으면 이 가정이 깨질 수 있음

**확인 필요**: 위 5개 항목은 아직 하나도 확정(Confirm)되지 않음. 4단계(Confirm) 또는 실제 데이터 확보 시 정합성 검증에서 다뤄야 함.

## 4. Confirm — 의미 확인

- "한 행 = 한 사번 × 한 기간(월/분기)"이라는 구조는 확인함
- **확인 필요**: 재직상태='퇴사'가 정확히 언제 시점 기준으로 반영되는지(데이터 스냅샷 시점)는 명시적으로 확인하지 않음
- 재직상태 ↔ 퇴사이력 교차검증은 완료 (양방향 불일치 없음 확인)

### 4-1. 신규 구간 데이터(`HR_근태_2026_1분기_원본수령분.xlsx`) — Profile 3-1 항목 확인 결과 (2026-08-01)

Profile 단계에서 남긴 5개 불확실 항목을 생성 로직 기준으로 확인함:

| # | 항목 | 확인 결과 |
|---|---|---|
| 1 | 그레인 혼재(사번×월 vs 부서×월) | 설계상 의도된 혼재. 상세 행(269개)=사번×월, 소계 행(6개)=부서×월로 명확히 구분됨 → 정제 시 소계 행은 검산용으로만 쓰고 본 데이터에서 분리 필요 |
| 2 | 기간 정보가 행에 없음 | 실제로 셀 값엔 없음, 시트 이름에만 존재 → 정제 시 시트명에서 연월을 파싱해 `년월` 컬럼으로 명시 필요(기존 `HR_근태.csv`와 스키마 일치시키기 위함) |
| 3 | 기본근무시간(160)이 관측값인지 | 고정 가정값(전 행 동일 하드코딩). "실제 관측치"로 취급하면 안 됨 |
| 4 | 이상근태(빨강) 판정 기준 | 두 규칙이 OR로 결합: ① 사번=E0137이면 무조건 이상, ② 그 외엔 해당 월 초과근무가 부서 평균의 2.2배 초과 시 이상 → 정제 시 규칙 통일 또는 별도 플래그 컬럼 분리 필요 |
| 5 | 269명 매달 전원 등장 | "재직자 명단 기준으로 무조건 다 채움" 방식이라 월별 중도입사/퇴사/휴직 변동을 반영하지 않음(알려진 한계) |

**확인 필요**: 위 5개는 합성 데이터의 생성 규칙으로서만 확인된 것 — 실제 인사팀 데이터가 같은 그레인·규칙을 따를 것이라고 일반화하면 안 됨. 실제 원본 확보 시 처음부터 다시 확인 필요.

## 5. Clean — 정제

**실제로 있었던 문제**: HR_직원.csv 재업로드본의 부서/직급/재직상태 필드가 인코딩 손상으로 깨짐 (원인: UTF-8 저장 중 일부 바이트 유실 추정)

**정제 규칙**: `HR_데이터_정제규칙.md`에 9개 규칙으로 문서화 완료 (인코딩, 키값, 날짜형식, 범주형 화이트리스트, 결측치, 정합성, 이상값, 중복행, 재업로드 체크리스트)

**정제 스크립트**: `clean_hr_직원.py` — 아래 순서로 재실행 가능하게 만듦
1. 표준 UTF-8 로드 시도
2. 실패 시 바이트 단위 필드별 재디코딩(UTF-8→cp949)
3. 그래도 화이트리스트 위반이면 신뢰 스냅샷과 사번 기준 병합 복구
4. 최종 검증(화이트리스트 통과 여부) 후 저장

**검증 결과** (오늘 실행):
- 손상 재현 파일(300행) → 원본과 100% 일치 복구 확인
- 멱등성 확인: 정제된 파일에 재실행해도 동일 결과
- 행 수 무관 동작 확인: 50행 부분 데이터에서도 하드코딩 없이 작동

### 5-1. 신규 구간 데이터(`HR_근태_2026_1분기_원본수령분.xlsx`) — 정제 결과 (2026-08-01)

**정제 규칙** (Confirm 4-1 결과를 그대로 반영):

| # | 규칙 | 처리 방식 |
|---|---|---|
| 1 | 그레인 분리 | 상세 행(사번×월)만 본 데이터, 소계 행(부서×월)은 검산 전용으로 분리 |
| 2 | 기간 컬럼 생성 | 시트 이름에서 "년월"(2026-01 등) 파싱해 명시적 컬럼으로 채움 → 기존 `HR_근태.csv` 스키마와 통일 |

**검증 결과**:
- 소계 행 대조: 부서×월 18개 조합 전부 일치(오차 0.05시간 미만) — 정제 로직이 원본 소계와 정확히 맞아떨어짐을 확인함
- 이상근태 플래그: E0137이 3개월 내내(68.9h/66.9h/74.9h) `True`로 정확히 잡힘
- **멱등성 확인** (2026-08-01): 같은 원본 파일로 스크립트를 두 번 실행해 결과 CSV를 `diff`로 비교 — 완전히 동일함
- **행/시트 수 변동 대응 확인**: 시트를 4개(2026년4월 추가)로 늘린 테스트 파일에 코드 수정 없이 실행 → 1,076행(269명×4개월)으로 정상 확장 인식됨

**산출물**: `HR_근태_2026_1분기_정제.csv` (807행 = 269명 × 3개월), 컬럼: 사번/부서/년월/기본근무시간_가정값/초과근무시간/원본이상근태플래그

**확인 필요**: 아직 기존 `HR_근태.csv`(2025년분)와 실제로 합쳐(concat)보지는 않음 — 컬럼명·타입이 스키마상 일치하는지 확인은 됐지만, 실제 병합·중복행 검사는 다음 단계(정합성·조인 검증 또는 Model)에서 진행 필요.

**Day5 교안 대비 프로세스 점검 (2026-08-01)**: 교안은 "규칙 제안 → 사용자 승인 → 실행 → 문서화 → 스크립트화 → 검증" 순서를 권장하는데, 실제로는 규칙을 세우자마자 바로 실행·검증까지 한 번에 진행한 뒤 문서화·스크립트 정리를 나중에 별도로 진행함 — 결과물 내용은 동일하지만 "승인" 확인 지점 없이 진행된 점은 다음부터 개선할 부분으로 기록함.

## 6. Model — 파생 지표 정의

- 근속연수 = (퇴사일 또는 기준일 - 입사일) / 365
- 평가점수 = 등급(S~D)을 5~1점으로 환산
- 채용경로 화이트리스트: 공채/수시/추천/헤드헌팅
- **추정연봉(⚠️ 공개 데이터 대체, Day3 확보경로 ④)**: 실제 급여 데이터 회신 대기 중 → 잡코리아 직급별 평균연봉 공개 통계로 임시 대체. 반드시 "실제 아님"을 명시하고, 실제 데이터 도착 시 폐기·재계산 예정

## 7. Analyze — 지표 계산

- 부서/직급별 퇴사율, 근속연수별 이탈 분포, 퇴사 직전 초과근무 신호
- 채용경로별 비중·퇴사율·근속연수 (추천채용 퇴사율 0% 발견, 표본 27명)
- 분기별 성과 추이 (전사 +0.18, 개발부서 +0.83)
- **인건비 효율(추정치)**: 개발 부서가 성과점수당 인건비 효율 최고(1,418만원)이면서 동시에 퇴사율도 최고(19.2%) — 낮은 처우와 이탈의 관계 가능성. 공개 통계 기반이라 확정적 결론 아님

## 8. Validate — 대조 검증

**✅ 완료.** 두 단계로 검증함:

1. **내부 재계산 대조**: 5개 항목(전체/퇴사 인원, 채용경로별 퇴사율, 부서별 퇴사율, 키 정합성, 재직상태↔퇴사이력 정합성)을 독립적으로 재구현해서 대조 — 전부 일치
2. **외부 원본 대조**: 인사팀 원본 채용 대장과 대조 확인 완료 — **일치함** (2026-08-01 확인)

→ 계산 로직 정확성과 원본 데이터 정확성 둘 다 확인됨. 이 단계에서 더 이상 남은 "확인 필요" 없음.

### 8-1. 신규 구간 데이터 — 기존 `HR_근태.csv`와 대조 검증 (2026-08-01)

**스키마 일치 확인**: 신규 정제 데이터(`사번/부서/년월/기본근무시간_가정값/초과근무시간/원본이상근태플래그`)에서 기존 스키마와 겹치는 3개 컬럼(`사번/년월/초과근무시간`)만 추려 병합 가능 여부 확인 — dtype 일치(둘 다 float64), 컬럼명 동일.

**대조 결과**:
- 키(`사번×년월`) 중복 0건 (기존 2025-01~12월, 신규 2026-01~03월로 기간 겹치지 않음)
- 신규 데이터에 없는 기존 사번 31명 = 퇴사이력 31명과 정확히 일치(재직자만 반영했으므로 정상)
- 병합 후 4,407행(=3,600+807), 결측 0건, 중복 0건 — **부서 단위 소계 대조(Clean 5-1의 18건)도 유지됨**

**⚠️ 개인 단위 연속성 문제 발견**: 2025년 개인별 평균 초과근무시간과 2026년 1분기 개인별 평균의 상관계수가 **0.279**로 낮음. 269명 중 165명(61%)이 개인 평균이 5시간 이상 급변(예: E0008 4.4h→15.0h). **원인**: 2026년 데이터를 합성 생성할 때 개인별 과거 패턴이 아니라 부서 평균 기준으로 생성했기 때문(생성 로직의 한계, 정제 오류 아님).

**판단(2026-08-01)**: 현재 대시보드(`app.py` ③번 차트)는 부서 단위 평균만 사용하므로 이 문제로 왜곡되지 않음 — 이대로 Publish 진행. 단, **개인별 근태 추이를 다루는 기능을 나중에 추가한다면 이 데이터는 그 용도로 신뢰할 수 없음**(기록만 남기고 이번엔 재생성하지 않기로 결정함).
